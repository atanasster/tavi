# Release notes

1. Start with one line: the version and its date, as `## 2.1.0 (3 November 2026)`.
2. Group the changes under **New**, **Fixed** and **Changed**, in that order. Leave out a group with nothing in it.
3. Write each change as one short line a user understands: what they can now do, or what no longer goes wrong.
4. End with a line thanking whoever reported a fixed bug, when the request names them.
